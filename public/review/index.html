Module 1Introduction to Routing

Key ideas

  • Routing computes paths and builds forwarding tables; forwarding just reads one row per packet.
  • The Internet is a network of autonomous systems (ASes): stub, multi-homed, transit. So routing splits into intra-AS and inter-AS.
  • Distance-vector = distributed Bellman–Ford: each router relaxes using only its neighbours’ vectors, and re-sends its own vector when it changes.
  • Link-state: routers flood their link costs, all build the same map, then each runs Dijkstra.

  • Count-to-infinity: after a link gets worse, neighbours keep quoting each other’s stale cost.
  • Poison reverse advertises ∞ back to your next hop. It breaks a two-router loop, not one through three or more.

Module 2Routing and Addressing at Internet Scale

Intra-AS

  • RIP: distance-vector, cost in hops, periodic Responses. Infinity = 16, so the longest path is 15 hops.
  • OSPF: link-state, floods advertisements; a large AS is split into areas to save memory and speed convergence.

Inter-AS: BGP (path vector)

  • eBGP learns AS-level paths between ASes; iBGP spreads them to every BGP speaker inside the AS.
  • Import (LOCAL_PREF): customer > peer > provider. Export: customer routes to everyone; peer and provider routes to customers only.
  • Route choice at one router: LOCAL_PREF → shortest AS_PATH → lowest intra-AS cost to the exit.

Addressing

  • NAT maps private (IP, port) ↔ public (IP, new port) in a translation table; replies are matched by the public port.
  • IPv6: 128-bit addresses (48-bit routing prefix, 16-bit subnet, 64-bit interface). Across IPv4-only routers: translation (lossy) or tunnelling (IPv6 packet inside an IPv4 packet).

Watch out

  • Longest-prefix match: if several entries match, the longest prefix wins, e.g. /23 beats /20.
  • NAT rewrites the port as well as the address.

Module 3Error Detection and Correction

Error detection

  • The sender adds redundant bits computed from the data; the receiver recomputes them and compares. A mismatch reveals an error.
  • Schemes: parity check (single and 2-D), Internet checksum, Cyclic Redundancy Check (CRC).

Error correction (FEC)

  • Forward error correction repairs errors at the receiver itself, without a retransmission.
  • The encoder maps each k-bit data block to an n-bit codeword (n > k); the extra n − k bits are the redundancy.
  • Schemes: 2-D parity (corrects a single-bit error), block codes.

Minimum Hamming distance decoding

  • Hamming distance d(v1, v2): the number of bit positions where they differ, e.g. d(011011, 110001) = 3.
  • Decoding: a valid codeword → output its data block. Otherwise an error is detected; output the block of the nearest codeword, if it is unique.
  • A code’s minimum Hamming distance d is the smallest distance between any two of its codewords.
corrects up to ⌊(d − 1)/2⌋ bit errors
detects  up to d − 1 bit errors

Module 5Network Transport Layer Protocols

Basics

  • Demultiplexing: UDP by destination IP + port; TCP by the 4-tuple (both IPs and ports).
  • UDP: connectionless, unreliable, 8-byte header. TCP: reliable byte stream; opens with SYN, SYN+ACK, ACK, closes with FIN/ACK each way.
  • Sequence numbers count bytes from the ISN; an ACK names the next byte expected. SYN and FIN each use one sequence number.
  • One timer, for the oldest unACKed segment. Timeout → resend that segment; 3 duplicate ACKs → fast retransmit.

Flow and congestion control

RcvWindow = RcvBuffer − (LastByteRcvd − LastByteRead)
nextseqnum − base ≤ min(CongWin, RcvWindow)
sending rate ≈ CongWin / RTT
  • Slow start: +1 MSS per ACK (doubles every RTT) until CongWin ≥ ssthresh.
  • Congestion avoidance: +1 MSS per RTT (AIMD: additive increase, multiplicative decrease).
  • Any loss, in either phase: ssthresh = CongWin / 2. Then:
    • timeout → CongWin = 1 MSS, slow start;
    • 3 duplicate ACKs → CongWin = ssthresh + 3, fast recovery; on a new ACK, CongWin = ssthresh, congestion avoidance.

Module 6Network Applications

Web and HTTP

  • HTTP runs over TCP and is stateless. Non-persistent: 2 RTT + transmit per object; persistent: ~1 RTT per object; pipelined: requests sent without waiting.
  • Request line method URL version; response line version code phrase (200, 301, 404). Then field: value header lines, in any order, a blank line, the body.
  • Cookies add state: Set-Cookie in a response, Cookie in later requests. A web cache answers hits itself; on a miss it fetches and keeps a copy.

DNS

  • Maps hostnames to IP addresses, and aliases to their canonical hostnames.
  • Distributed hierarchy: root → TLD → authoritative; a local DNS server answers clients and caches records for their TTL.
  • Recursive: “get me the final answer” (client → local). Iterative: “tell me what you know”, answered with the answer or a referral (local → root, TLD, authoritative).
